# ADR 0005 — MCP tools map 1:1 to canonical verbs

**Status:** accepted · **Amends:** A5 · **Affects:** `src/mcp/server.ts`,
MCP schema, `tests/mcp/parity.spec.ts`

## Context

`src/mcp/server.ts:81` states the constraint in the source itself: the
MCP tool catalog is _"1:1 mappings to canonical verbs, nothing else"_.
A `toolCatalogDigest` (`:672`) records provenance of that catalog.

The v6 spec proposes 11 new tools. Under a 1:1 rule those 11 must
resolve to **existing** canonical verbs with sub-selectors, because a
tool that does not map to a verb is a second, parallel tool surface —
and two tool surfaces on one engine is precisely how verdicts start
disagreeing between a CLI consumer and an agent consumer.

## Decision

**The 11 proposed tools resolve to 8 canonical tools with
sub-selectors. No new tool semantics are introduced.**

| Spec's proposed tool | Canonical tool | Selector           |
| -------------------- | -------------- | ------------------ |
| `scan_repository`    | `scan`         | —                  |
| `get_findings`       | `scan`         | `select: findings` |
| `explain_finding`    | `explain`      | `target: rule`     |
| `get_rule`           | `explain`      | `target: rule`     |
| `get_capability`     | `capability`   | `op: get`          |
| `get_maturity`       | `capability`   | `op: get`          |
| `get_next_level_gap` | `capability`   | `op: get`          |
| `get_impacted_tests` | `impact`       | —                  |
| `trust_report`       | `trust-report` | —                  |
| `evaluate_policy`    | `policy`       | `op: evaluate`     |
| `report`             | `report`       | `select: format`   |

Rules that follow from the mapping:

1. **One canonical verb, one semantics.** A tool never gains behaviour
   its verb does not have. `explain` explains; it does not re-scan.
2. **The `toolCatalogDigest` is preserved and extended**, not replaced.
   It becomes the provenance record that also proves _parity_: the same
   repo + SHA + config + tool version through MCP must yield the same
   canonical result as through the CLI.
3. **A tool that cannot map is a signal, not a tool.** If a future
   requirement cannot be expressed through the canonical verbs, the
   answer is a _selector_ or a new **verb** with the removal/merge cost
   the anti-bloat rule (§6.12) requires — never a tool that bypasses the
   verb set.
4. **Backward awareness.** The MCP schema is versioned. Additive-only
   per `docs/VERSIONING.md`; a major version is the sanctioned moment for
   a break.

## Consequences

**Forbids**

- An MCP tool that is not a 1:1 mapping to a canonical verb.
- MCP-specific verdict logic: the tool must call the same engine the CLI
  calls, not re-derive anything.
- Silently changing a selector's semantics; a selector change that
  alters a verdict is a contract break.

**Costs**

- 11 spec-proposed tools become 8. Some agent use cases that read
  naturally as their own tool are served by a selector, which is a
  marginally worse ergonomics story in exchange for a single verdict
  path.

## Rejected alternatives

| Alternative                                   | Why rejected                                                                                                                               |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Adopt the 11 tools as specified               | Breaks the 1:1 rule that is written into the source, and creates a second verdict path.                                                    |
| Adopt 11 tools that each _delegate_ to a verb | Delegation without 1:1 still leaves 11 public names that can drift in behaviour, ordering and defaults — drift with a nicer surface.       |
| One mega-tool with a `method` field           | Hides the contract from schema consumers and makes per-tool versioning impossible. Sub-selectors on 8 named verbs keep the schema legible. |

## Enforcement

| Mechanism           | Location                                                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Catalog declaration | `src/mcp/server.ts` — each entry declares its canonical verb; a tool with no verb is a construction error                                |
| Catalog digest      | `toolCatalogDigest` — regenerated by the catalog builder, drift-locked                                                                   |
| Parity              | `tests/mcp/parity.spec.ts` (existing) extended to the 8 tools; Wave 10 adds `surface:parity` across CLI/Action/MCP/VS Code/App/Dashboard |
| Contract tests      | `tests/contract/version-surface.spec.ts` — MCP schema versioning                                                                         |
