# Reference Interaction Patterns

This note records the interaction patterns studied before the QA Doctor
homepage refresh. It is a design reference, not product documentation.

## OmniRoute

[OmniRoute](https://www.omniroute.online/) leads with one concise promise,
then makes its system legible in progressively deeper layers: an immediate
entry point, a catalog of supported options, focused controls, and a staged
quick-start path. The useful pattern for QA Doctor is not its visual identity;
it is the clear explanation of a complex tool in the order a new user needs it.

QA Doctor adopts that logic through an early `Run -> Diagnose -> Protect`
sequence, followed by the existing detailed evidence, score, rule, CI, and
agent material.

## Open Code Review

[Open Code Review](https://open-codereview.ai/) combines a dark technical
surface, subtle moving diagnostic elements, a terminal example, and an
install/configure/run quick-start sequence. Its companion
[open-source repository](https://github.com/alibaba/open-code-review) confirms
that this quick start maps directly to real commands rather than decorative
copy.

QA Doctor translates the pattern into a brief branded diagnostic boot, a
measurement-grid background, live scan signals, and copyable commands. Motion
is reduced-motion aware, and diagnostic colours remain semantic: critical is
reserved for failures, attention for review, healthy for verified health, and
gold for quality or a deliberate next action.

## Guardrails

- Do not recreate either reference site's brand, logo, content, or layout.
- Keep the page readable without JavaScript and usable with reduced motion.
- Treat visual effects as system feedback, never as decorative light shows.
- Keep the product narrative connected to QA Doctor's real CLI and CI flows.
