# Manual scripts

**P0-10.** `package.json` carries scripts that no workflow step runs and no
other script chains to. Nothing failed: an npm script reachable from nothing is
indistinguishable from a script that does not exist.

`npm run scripts:reachable` fails when a script is neither reachable from a
workflow (transitively, through `npm run` chains) nor listed here. Two
neighbouring gates each answer half of this and neither answers the whole:

- `check-gate-tiers.mjs` asks whether a **declared** gate has a step. It says
  nothing about scripts nobody declared.
- `check-unimported-modules.mjs` asks whether a **script file** is invoked. A
  script reachable only as a member of a chain looks orphaned to it by
  construction.

Every row below is a decision, not an absence. The reason is the part a
reviewer needs to check, so the gate rejects a one-word reason — "manual" is a
category, not a reason. A row for a script a gate _does_ reach is itself a
failure: a script cannot be both.

## The categories, and what would close each

- **DEV** — an interactive entry point a human types. A gate cannot invoke a
  long-lived process, and closing this row means never.
- **WRITE** — a generator or updater with a write mode. Running it in CI would
  rewrite tracked files, which is exactly the drift the staleness gate exists
  to catch. Closed by joining the `docs:regen` chain, when its output is meant
  to stay fresh per commit.
- **RELEASE** — a release-path step run by a human against a release branch.
  Closed by automating the release, or by a runbook.
- **TOOL** — a one-shot or investigative tool with no cadence. Closed by
  deleting it, once its answer is in a committed artifact.
- **ADVISORY** — a report that is deliberately non-blocking. Its strict variant
  is the one that gates, or the arm that refuses for the thing to get worse.
  Closed by promoting the strict variant when the gap closes.
- **REACHABLE-BUT-UNWIRED-IN-CI** — reachable from the LOCAL chain but not
  from any workflow. A variant is left unwired when gating on it would make
  every build red for a reason nobody can fix in the diff, which is how a gate
  gets switched off. `tests/stress` is the current instance: it is reached
  from `npm run test` locally and runs in its own workflow, but a failure
  inside it must not be able to hold a pull request hostage to a machine
  nobody owns.
- **ALIAS** — a second name for something already gated. Closed by deleting the
  alias; it exists because the shorter name is the one a human types.

Two scripts are accounted for without a row, and deliberately so:

- **`prepare`** — npm runs it on `npm install` to install husky. The gate
  treats it as a root for exactly that reason, so it is reachable and a row
  would be a failure.
- **`prepublishOnly`** — npm runs it on `npm publish`. Nothing names it and
  nothing chains to it, so it is in the gate's `NPM_LIFECYCLE` set instead of
  the table: it is npm's contract rather than this repository's decision, and
  special-casing it in the checker keeps the exception visible in code next to
  the rule it bends.
