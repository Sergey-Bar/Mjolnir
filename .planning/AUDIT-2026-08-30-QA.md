## Findings

### QA-1 — P0 · functional/detection regression · `src/rules/test/qa-test-003-no-assertions.ts`

**Evidence.** The M0-#4 rewrite tightened the arrow-callback regex from
`(?:async\s*)?` to `(?:async\s+)?`, so `it("x", async()=>{ … })`
(no space) stopped matching entirely. The M0 spec only ever tested
`async () =>` with a space. Corpus proof: withastro-astro QA-TEST-003
went 100 → 76 (−24) — reproduced on a pinned astro snapshot with the
baseline commit (9782c77) vs the working tree.

**Fix.** Restore `(?:async\s*)?` inside the M0-#4 alternation (spaceless
arrows) while keeping the function-body alternative and the narrowed
`return expect|assert` exemption.

**Regression test.** `tests/audit-qa2026-08-30-fixes.spec.ts` →
"QA-1": must-fire on spaceless async, must-fire on spaced async (M0
preserved), must-not-fire on an asserting spaceless-async test.

### QA-2 — P0 · functional/detection regression · `src/discovery/scan-adapters.ts`

**Evidence.** `discoverAllTestFiles` walked with the UNION of every
language adapter's `dirSkips`. `pythonAdapter.dirSkips` contains `env`
(virtualenv), `javaAdapter.dirSkips` contains `build` (Gradle output) —
as a union these hid ANY directory with those names from EVERY language.
withastro/astro's `packages/astro/test/units/env/` (24 QA-TEST-003
findings) and `packages/astro/test/units/build/` (1 QA-PW-120 finding)
silently disappeared from scans. Bisected via a same-clone scan with the
baseline commit (100/38/4 = committed baseline) vs the working tree
(76/33/3); `typescriptAdapter.discoverTestFiles` found 818 files vs the
union walk's 803.

**Fix.** The shared walk descends into every non-ignored directory; the
OWNING adapter's `dirSkips` are applied per file (`isInsideSkippedDir`).
Walk-level skips are now the intersection across adapters (empty today).
This preserves each language's pre-single-walk discovery semantics
exactly while keeping the single-walk performance win (P-2).

**Regression test.** wave spec → "QA-2": TS test files inside `env/` and
`build/` dirs are discovered; a Python file under `env/` is still
skipped (must-not-discover).

### QA-3 — P1 · edge · `src/rules/shared/masking.ts`

**Evidence.** `enclosingMaskedRun` expanded the masked run while
`isMasked(...) === true`, but `isMasked` cannot distinguish a masked
whitespace character from live code whitespace (both read `" "`), so the
run truncated at the first space inside a literal. For
`'test(" foo", function () {})'` the run became `'test("'`; the helper
then stripped the trailing nested `"` as if it were the delimiter, found
no nested quote, and classified embedded test-data as live code.
Manifested as 6 QA-TEST-003 false positives on
playwright-community/eslint-plugin-playwright's ruleTester tables (and
1 QA-TEST-010), surfacing through the M0-#4 function-body alternative.

**Fix.** Expand while the mask reads `" "` (masked chars of any kind) and
stop only at live non-whitespace — the string's closing delimiter is
always followed by live non-whitespace, so the expansion stays inside
the literal.

**Regression test.** wave spec → "QA-3": no QA-TEST-003 fire on test-data
strings with spaces; helper classifies the offset as embedded; a plain
value literal still leaves the rule live.

### QA-4 — P1 · security · `src/config/config.ts`, `src/discovery/ignores.ts`

**Evidence.** `validate()` never checked `exclude`; `loadExtraPatterns`
pushed `cfg.exclude` array items unchecked and `compilePattern` called
string methods on them — `exclude: [1, {}, null]` crashed with a
TypeError (exit 20 "tool malfunction") instead of a fixable usage error.

**Fix.** `QADoctorConfig.exclude?: string[]` documented; `validate()`
requires an array of strings (throw → `ConfigValidationError` → exit 10,
M4 convention, message states the fix); defense-in-depth `typeof` filter
in `loadExtraPatterns` and `compilePattern`.

**Regression test.** wave spec → "QA-4": loadConfig throws
`ConfigValidationError` with a fixable message for non-strings and
non-array; hostile matcher does not crash; must-not-fire: a valid string
exclude still excludes end-to-end.

### QA-5 — P1 · security · `src/config/config.ts`

**Evidence.** `new Date(ign.expires)` on garbage yields NaN; NaN
comparisons are always false, so an unparseable date silently degraded
to "expired" (or active) with no signal.

**Fix.** `validate()` rejects unparseable `expires` values with a
fixable message (exit 10).

**Regression test.** wave spec → "QA-5": `expires: "next tuesday"` is
rejected with the fix stated.

### QA-6 — P1 · usability/documented behavior · `src/config/config.ts`, `src/config/suppressions.ts`

**Evidence.** README §Configuration promises "`ignore` entries expire
after 90 days", but `isSuppressionActive` returned `true` forever for
hand-written entries without `expires` (the 90-day default was only
applied at write time by the `ignore` command).

**Fix.** The default is enforced at enforcement time, anchored at the
config file's mtime (`loadSuppressions` threads the anchor; the `ignore`
command's write-time behavior is unchanged). `mjolnir suppressions`
labels no-expiry entries explicitly: "(no expiry set — 90-day default
from config mtime)" / "(… default elapsed)". README table updated to
state the exact semantics.

**Regression test.** wave spec → "QA-6": stale-mtime no-expiry entry is
inactive; fresh config is active and labeled; explicit `expires` keeps
write-time semantics.

### QA-7 — P1 · security · `src/plugins/load.ts`

**Evidence.** The reserved-prefix spoof check was case-sensitive:
`r.id.startsWith(p)` — a plugin rule id `"qa-test-001"` bypassed
rejection. Verified `RESERVED_PREFIXES` covers every shipped family
(QA-TEST/TQUAL/PW/CI/PY/ENV/JV/CS/PLUGIN — grep of the registry).

**Fix.** Compare `ruleId.toUpperCase()` against the reserved list.

**Regression test.** wave spec → "QA-7": lowercase-spoofed plugin rule
is rejected with the reserved-prefix error.

### QA-8 — P2 · edge · `src/cli.ts`

**Evidence.** `pathMatchesGlob` split the glob on `/` only and escaped
`\` as a literal — a `files` pattern written on Windows
(`"e2e\\x.spec.ts"`) could never match any finding (findings carry
normalized `/` paths); the suppression silently never applied.

**Fix.** Normalize both sides to forward slashes before compiling.

**Regression test.** wave spec → "QA-8": backslash patterns match
normalized paths (and vice versa); must-not-fire: unrelated path.

### QA-9 — P2 · security · `src/scope/changed.ts`

**Evidence.** `--base` values reach `git merge-base HEAD <candidate>` in
array form (no shell). `parseArgs` already rejects `-`-prefixed values
(H-10), but a programmatic caller could pass
`--upload-pack=x`, which makes git itself run an attacker-chosen
command.

**Fix.** Defense in depth: `resolveMergeBase` skips option-shaped
candidates (degrades to `no-merge-base` instead).

**Regression test.** wave spec → "QA-9": parseArgs rejects the hostile
values (usage error); legitimate refs parse; the resolver degrades on
an option-shaped base.

### QA-10 — P2 · security · `src/reporter/theme.ts`, `src/reporter/terminal.ts`, `src/commands/pr-comment.ts`

**Evidence.** Finding metadata (file paths — hostile filenames are
possible; plugin rule ids and messages — arbitrary plugin strings) is
rendered to the terminal and into the markdown PR comment unsanitized:
ANSI ESC sequences pass through palette helpers, raw `f.file`/`f.ruleId`
interpolations bypass them entirely, and `findingLine` embedded raw `|`,
backticks and `</script>` into the PR comment body.

**Fix.** `sanitizeData()` (CSI/OSC/C1/C0 stripping, tab/LF preserved)
applied inside every palette helper (colored and uncolored) and at the
raw terminal interpolation sites; `escapeMarkdown` in pr-comment escapes
markdown-significant characters and sanitizes.

**Regression test.** wave spec → "QA-10": hostile payload renders inert
in colored and uncolored modes; control chars stripped, tab/LF kept; PR
comment line escapes `|`, backticks, `<script>` with only the intentional
code-span delimiters unescaped.

### QA-11 — P2 · performance · `src/forensics/parse-junit.ts`

**Evidence.** The `<testcase` iteration used a lazy
`([\s\S]*?)<\/testcase>` inner scan; a flood of unclosed `<testcase`
starts made every start rescan the rest of the input — quadratic. On the
20 MB MAX_INPUT budget this is minutes of CPU for a hostile report. NOT
covered by redos-audit (which exercises rules, not the forensics
scanner) nor forensics-edge.

**Fix.** Linear scan: regex-locate starts, `indexOf` the attribute
terminator, `exec` the closer from `lastIndex`; the first unclosed
`<testcase` terminates the loop (no later start can close either).
Behavior-preserving for valid input (all forensics suites pass
unchanged). Also escaped `attr()`'s name argument as future-proofing.

**Regression test.** wave spec → "QA-11": 20 MB unclosed flood parses in
< 2 s returning zero records; a valid large report after hostile noise
still parses exactly.

### QA-12 — P2 · security · `src/commands/baseline.ts`, `src/commands/stats.ts`

**Evidence.** `loadBaseline` accepted any `findings` array — `null`
entries crashed `diffAgainstBaseline` (`f.ruleId` on null → exit 20).
`loadStats` accepted any `resolvedByRule` — string values concatenated
junk into `renderStats` totals (`"abc1"`-style folds from
`recordedFixEvents`).

**Fix.** Totality guards (M3-style): baseline entries are filtered to
well-formed {ruleId, file, message} objects; stats shapes are coerced
(numeric values only, `recordedFixEvents` finite ≥ 0 else 0, `trackingSince`
string else "unknown"); the sanitized shape is what gets re-saved.

**Regression test.** wave spec → "QA-12"/"QA-12b": null-laden baseline
loads and diffs; hostile stats coerced and renders honest numeric totals;
non-object `resolvedByRule` loads empty.

### QA-13 — P3 · hardening · `src/reporter/sarif.ts`

**Evidence.** `encodeURI` leaves `\` literal — an invalid RFC 3986
uri-reference character. Finding paths are walker-normalized, but the
reporter must not emit an invalid URI for a raw path. Verified no caller
passes a `repoRootUri` (cli passes none), so `originalUriBaseIds` is
correctly absent.

**Fix.** Normalize `\` → `/` before encoding.

**Regression test.** wave spec → "QA-13": a `e2e\checkout.spec.ts`
finding renders `e2e/checkout.spec.ts`, no backslash in the SARIF output.

### QA-14 — P2 · edge (test suite) · `tests/hostile-repo.spec.ts`, wave spec

Adversarial repo shapes: 40-level deep nesting (depth cap respected),
`#`/space/unicode filenames end-to-end, 2 MB+ files, junction-style
symlinks out of the scan root (never followed), malformed workflow YAML,
malformed JUnit XML shapes, hostile Playwright JSON reports — all handled
without crash or hang, exit codes inside the documented set.
NB: `?` is an unrepresentable filename character on Windows; its literal
handling is pinned by the `pathMatchesGlob` escaping tests (QA-8).

### QA-15 — P1 · functional · `src/engine/ts-ast.ts`

**Evidence.** `getCodeOnlyText` built the mask with `[...text]`, which
iterates CODE POINTS: one astral char (emoji = surrogate pair) collapsed
to a single element, so the mask array was one code unit shorter than
the text and every ts-morph UTF-16 offset after it was misaligned.
`isMasked`'s length guard then silently disabled masking for the entire
file — found because a test-fixture filename containing 🪓 made the
repo's own self-scan fire QA-TEST-003 on template-literal test data
(self-scan regressed 100 → 95).

**Fix.** `text.split("")` — UTF-16 code-unit indexing, matching String
offsets (the adjacent comment already claimed this contract).

**Regression test.** wave spec → "QA-15": mask length equals text length
with an emoji present; embedded-code masking stays enabled after an
astral char.

**Corpus consequence (reviewed).** QA-PW-105/108 match against
`ctx.codeText`; the pre-fix misaligned mask shifted their offsets on any
file containing an astral character, losing matches (+27 vite
QA-PW-105, +22 tanstack-query QA-PW-108, +1 astro QA-PW-105 after the
fix). Mechanism verified by reading the rules' match surface; accepted
via the reviewed `--update`.

### QA-16 — P2 · functional/honesty · `src/discovery/shared-walk.ts`

**Evidence.** Files larger than `LIMITS.maxFileBytes` were dropped in
the walk with neither `onTestFile` nor `onSkipped` — never scanned,
never counted: a scan could claim `complete` while silently ignoring
megabytes of test code.

**Fix.** The size skip calls `onSkipped("file-size")` — counted in
`analysisStatus.skippedFiles`, named in `truncationReasons`, and
`partial` is flagged.

**Regression test.** `tests/hostile-repo.spec.ts` → "QA-16": a 2 MB file
is counted, the reason recorded, partial flagged, no findings from it.

## Suspected, not confirmed (recon items that checked out clean)

1. **Git arg injection via `--base`** — already hardened by H-10 at
   `parseArgs` (array-form exec, `-` values rejected). QA-9 adds
   defense in depth only.
2. **SARIF `repoRootUri` callers** — no caller passes a raw
   `process.cwd()`; `renderSarif` is called without `repoRootUri`
   everywhere in `src/`, so `originalUriBaseIds` is absent by design.
3. **JUnit ReDoS on closed-flood inputs** — the pathological shape that
   matters was the unclosed flood (QA-11); `<testcase`-less 20 MB input
   returns immediately via the MAX_INPUT guard.
4. **eslint-plugin-security / regexp lint gates** — `npm run lint` clean
   (prettier + eslint, regexp plugin active) at final validation.
5. **Terminal injection via `tone-blunt`/`badge`** — both render static
   or score-derived text only (`BLUNT_MESSAGES` is a static map; badge
   message is derived from the numeric score), no finding data flows
   through. The QA-10 fix covers the surfaces that do.
6. **`--scope changed` window `[f.line-3, f.line]`** — verified against
   `tests/scope.spec.ts`, `tests/git-scope-edge-cases.spec.ts` and the
   audit-h spec: multi-line-statement anchoring above added lines is
   covered; no widening needed for the documented use case.
7. **Adapters on adversarial encoding/shape inputs** — CRLF/CR mixes,
   UTF-16LE, BOM, zero-byte files, unreadable files, symlink loops,
   f-strings/Java text blocks/C# raw strings masking are all locked by
   `tests/adversarial-extended.spec.ts` and
   `tests/code-text-masking.spec.ts`; no new gaps found.
8. **CLI contract matrix** — unknown flags, non-numeric/≤0 `--width`/
   `--max-duration`, format combinations, partial → 2, empty-state
   `score: null`, advisory never blocks: locked by
   `tests/cli-flag-matrix.spec.ts`, `tests/cli.spec.ts`,
   `tests/empty-states.spec.ts`, `tests/cli-command-crash-paths.spec.ts`.
9. **Scorer invariants** — [0,100] bounds, monotonicity, floor at 0,
   empty = 100 with declarations / null without: locked by
   `tests/score-invariants.spec.ts` and `tests/property-invariants.spec.ts`.
10. **Corpus repo drift** — the live OSS repos move daily; residual
    count differences after the code-level fixes were attributed to
    upstream motion, spot-reviewed, and absorbed by the reviewed
    `--update` (documented in CHANGELOG "Changed — corpus baseline").
