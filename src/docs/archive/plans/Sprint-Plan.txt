# 0. PLAN CONSTANTS

## Team & Cadence
```text
Team:        1 senior developer + AI pair (Claude/Copilot)
Sprint:      1 week (Mon–Fri), demo every Friday to a non-author reviewer
Capacity:    5 days/sprint × ~6 focused hours = ~30h effective
Buffer:      Week 13 is hardening/buffer ONLY — no new features
Ceremonies:  Mon: pick tickets → Fri: demo + retro (30 min max)
```

## Definition of Ready (ticket level)
A ticket enters a sprint only if it has:
- [ ] Acceptance criteria written as testable statements
- [ ] Fixture files specified (for rules: must-fire AND must-not-fire)
- [ ] Dependencies on prior tickets resolved or stubbed

## Definition of Done (every ticket)
- [ ] Code merged via PR (even solo — self-review catches real bugs)
- [ ] Unit tests green; fixtures pass both directions (rules)
- [ ] Cross-platform note checked (no path separators, no shell-outs)
- [ ] Conventional Commit; changeset if user-visible
- [ ] No new findings from QA Doctor's own self-scan gate

## Standing CI Gates (from §30.2, activated progressively)
```text
From W1:  build, lint, unit tests, Windows+Linux matrix
From W2:  fixture harness, golden-repo mechanism
From W4:  fuzz corpus, perf benchmark
From W7:  no-network gate, self-scan gate
Always:   macOS added to matrix from W8
```

## Ticket ID Convention
`W{week}-{seq}` e.g. `W3-04`. Rules carry their rule IDs (`QA-*`).
